- **Corpus: 240 documents** (5 types × ~48) over 12 in-world month-end batches (Jan–Dec 2025); variants/failures placed months 8–12 so parsers exist before they're tested.

- **One extraction schema per type binds all three** — LLM output, generated parsers, answer key — so "correctly parsed" has a single definition.
- **Cost accounting**: two methods specified (A: real API calls, measured; B: subagents, estimated); recommendation A; labels tell the truth either way. Eva decides (open question 3).

## S-class relocation (2 Jul 2026, Phase 2 build review)

- **The silent error moved from FBL3N to ME2M.** Main-loop review of the generated corpus caught a flaw in the signed-off design: FBL3N's totals are S/H-split and label-matched ("Summe Soll" = sum of debit amounts), so a positional parser reading swapped amount/tax columns produces sums that cannot reconcile with the totals block under any extraction strategy — the router would catch it, and the pre-registered "silent" outcome would falsify itself. New mechanism: in one ME2M document (2025-11_ME2M_02), *Nettopreis* and *Noch offen Wert* swap positions, headers and values together; the totals column (*Nettowert*) does not move, so every declared router check (schema, totals, master-data) passes on a positional read. A line-level price × quantity cross-check would catch it — the router deliberately does not run one, and the writeup will state this as the production recommendation. Class counts became FBL3N 45R+3V, ME2M 42R+5F+1S (portfolio totals unchanged: 218/6/15/1; pre-registered headline numbers in design.md §4 unaffected).
- Corpus regenerated and revalidated after the change: all seven coherence rules pass; regeneration is byte-identical (verified by SHA-256 over all 480 files, twice).

## Ground-truth principle + two Phase 2 defects (2 Jul 2026, pre-parse review)

- **Principle (decided): the answer key is the ideal reading of the document, not the master data behind it.** Where a cell truncates a long string (H7 horror — e.g. VA05 *Lieferstatus* "Vollständig au", ME2M 22-char vendor names), the answer key stores the truncated rendered string. Scoring a parser against information absent from the text would measure clairvoyance, not extraction. The information loss itself is shown in the case study as a property of the source system, but not scored against either path.
- **Defect 1**: answer keys stored full master-data strings for truncated cells (found by comparing keys against rendered text before dispatching any parse agent). Fix: payload string fields take the stripped rendered cell value, per-document (widths jitter per doc); validator gains a verbatim-presence rule (every payload string must appear in the doc text) so this cannot regress.
- **Defect 2**: the VA05 renderer never printed its net-value totals line, though schema and design §3 require one — undetected because the from-text arithmetic recheck covered only FBL3N and ME2M. Fix: VA05 gets a "Gesamtsumme" line (ME2M convention); the from-text totals recheck is extended to all five types.
- Both fixes are constrained: no rng-order changes; all non-VA05 document texts must remain byte-identical to the current corpus (hash-verified); no parse agent had run yet, so nothing downstream is invalidated.
- **Correction (same day, post-fix):** Defect 2 was a false alarm — VA05 always rendered a totals line, labelled "Nettowert gesamt"; the reviewing grep used case-sensitive keys ("Gesamt"/"Summe") and missed the lowercase "gesamt". What actually changed: the label was renamed to "Gesamtsumme" for cross-type consistency, and the from-text recheck extension to all five types (the real hardening) stands. The builder flagged the contradiction rather than forcing the wrong premise — correct behaviour.
- **Third defect, found by the new verbatim rule:** the FBL3N V-class layout variant drops the *Referenz* column entirely, yet payloads carried reference values a reader of the document could not know. Under the ground-truth principle those payloads now hold null. All fixes verified personally: validator exit 0, truncation consistency spot-checked, 3/3 V-docs null references, regeneration byte-identical.

## S-class escalation + gate results (3 Jul 2026)

- **The overseer's ME2M parser defeated the layout-swap S mechanism.** It resolves columns by header label per page, so a document with swapped columns-plus-headers parses *correctly*. Iteration 3 of the S mechanism (escalation): headers stay canonical, the **values** of Nettopreis and Noch offen Wert are written into each other's columns — upstream corruption, "the document lies." No text-only reader can catch it; totals reconcile; only the answer key (in production: source-system reconciliation) sees it. **Answer-key exception, documented:** for this one document the key records what the system *should* have printed, deliberately breaching the ideal-reading rule — the breach is the measurement. The price × quantity cross-check catches it on parsed values (0,00 × 2.000 ≠ 7.480,00), which stays the production recommendation.
- **Regression gate: 5/5 parsers PASS** (each reproduces the accepted LLM parses on its 8 discovery docs). Full-corpus dry run (run personally): all 218 R docs parse and match, 16/16 V+F docs for FBL3N/VA05/ME2M raise as designed, the S doc is silently wrong as designed.
- **Pre-registration deviation, accepted and frozen:** all 5 FBL1N F-docs ("mid-table currency change") parse *correctly* instead of falling back — the generated parser treats currency as data (per the overseer brief) and handles mixed-currency vendors. The plant was defeated by parser quality. Decision: do NOT retrofit a harder trap; the designed-outcome table stays frozen and evaluation reports designed-F/actual-deterministic-correct. Empirical whole-stream deterministic share: **184/240 ≈ 77%** vs the pre-registered ≈75%. Together with the S iteration, this is the "the system beat our own traps, and pre-registration is what made that visible" thread for the writeup.

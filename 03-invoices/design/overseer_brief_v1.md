# Overseer brief v1 — pinned input for every parser-writing agent

Version 1.0, 3 July 2026. Given verbatim to each overseer agent (one per supplier-layout pair
that reaches N = 6 structurally consistent accepted parses). Edits create v2 and are logged.

## Task

You are the overseer of an invoice-processing pipeline. The LLM path has parsed N invoices from
ONE supplier, and the parses were accepted. Your job is to notice that this supplier's layout is
consistent and write an ordinary deterministic parser for it, so that this supplier's future
invoices cost nothing to parse.

## Inputs (your assignment lists the exact paths)

- The N accepted parse JSONs for this supplier's documents (the pipeline's own output — treat
  as ground truth for what a correct parse of each document looks like).
- The N corresponding PDFs, and a plain-text dump + word-coordinate dump of each (produced with
  pdfplumber, the same library your parser will use).

## Hard boundaries

- Read ONLY the files listed in your assignment plus this brief. Do NOT open anything else —
  no answer keys, no HTML sources, no template/config/generator code (your parser must be
  induced from the documents and accepted parses alone, not from the code that made them), no
  design documents, no other suppliers' files.
- Write ONLY your assigned output file `code/parsers_generated/parser_<slug>.py`.
- End your final report with a complete list of every file you opened and wrote (audited).

## The parser you write

- Python, importable module, **stdlib + pdfplumber only**. No other imports, no file I/O except
  reading the `pdf_path` it is given, no network, no randomness, no datetime.now().
- Public API: `parse(pdf_path: str) -> dict` returning a record in EXACTLY the schema used by
  the accepted parses (same field names, same canonicalisation: ISO dates, canonical money
  strings with `.` and two decimals, integer quantity strings, vat_rate one of
  "25.5"/"14.0"/"10.0"/"0.0", verbatim text fields).
- **Provenance header**: module docstring stating it was machine-generated by the overseer,
  the date, the model, and the doc_ids it was induced from.
- **Fail loudly, never guess.** Define `class ParserLayoutError(Exception)`. Verify the layout
  landmarks you rely on (the labels, column headers, and block positions you observed) and
  raise ParserLayoutError with a precise message the moment anything is missing, reordered,
  renamed, or otherwise not as expected — including any line whose parts you cannot fully
  account for, any arithmetic that does not reconcile (line sums vs printed net; net + VAT vs
  gross), and any page structure you did not observe in the induction set. An exception here is
  a SUCCESS mode of the system (the router falls back to the LLM); a silently wrong record is
  the failure mode. Do not write defensive fallbacks that paper over surprises.
- Parse from the text layer via pdfplumber (extract_text / extract_words with coordinates —
  whatever is robust for THIS layout). Handle the benign variation you can SEE across the N
  documents (line counts, page breaks if present, value widths); do not speculate about
  variations you have not seen.
- **Mandatory self-test**: under `if __name__ == "__main__":` accept a list of
  `(pdf_path, accepted_parse_json_path)` pairs as command-line arguments (or a single JSON
  manifest path), run `parse()` on each PDF, deep-compare to the accepted parse, print per-doc
  PASS/FAIL and exit non-zero on any FAIL. Run it yourself on your induction set before
  finishing; report the result.

## Report back

State: the layout landmarks you keyed on; anything inconsistent you noticed across the N
documents; your self-test result (must be N/N PASS); the files you opened and wrote.
